以下说明针对 2026-10-21 的开发源码，相关修复晚于已发布的 0.7.0。

## 目标路径规则

本地复制、上传、下载及传统 SSH 回退通道采用以下同一规则：

| 目标写法 | 行为 |
|---|---|
| 已有目录 | 在目录内保留源文件或目录名。 |
| 不存在、末尾有 `/` | 自动创建目录，保留源文件或目录名。 |
| 单个源、不存在的裸目标 | 作为新文件名或目录名。 |
| 多个源 | 要求目标是已有目录，或显式以 `/` 结尾。 |
| 完整文件路径、父目录缺失 | 自动创建父目录。 |
| 已有普通文件后加 `/` | 报错并保留原文件。 |
| dry-run | 使用相同路径解释，不建目录、不删除源文件。 |

```bash
bcp report.pdf new/test/                # new/test/report.pdf
bcp report.pdf 'host:~/new/test/'        # ~/new/test/report.pdf
bcp 'host:report.pdf' new/test/          # new/test/report.pdf
bcp -r project renamed                  # renamed/下直接放 project 的内容
bcp -r project new/                     # new/project/下放原内容
```

源目录末尾的 `/` 不会隐式切换为 rsync 风格的“只复制内容”。源路径的 `*` 在计算目标前统一展开一次。

## 覆盖与移动

普通文件复制需要 `-f` 才能替换已有目标；明确无人值守覆盖请用 `-f -y`。续传和追加保留各自的前缀验证规则。新的传统 SSH 下载会先暂存，读取、可选校验成功后再发布；失败时保留原目标。

多目标移动预演不会删除源文件。远程和多目标移动目前拒绝 `--exclude`，避免整体清理误删没有复制的排除项；可先带排除规则复制、验证，再删除明确需要移走的原文件。

## 仍未完全统一的部分

目前不能声明所有本地和远程行为完全一致：

- 远程 `-p` 对目录自身的属性保存、递归符号链接遍历仍不完整。
- 远程排除规则还没有完整统一父目录剪枝，传统上传也未完全遵循顶层排除规则。
- 本地移动通常使用重命名，远程移动是复制后删除，目录合并和失败时的原子性不同。本地重命名仍有已有的检查/重命名并发窗口。
- 强制的传统远程上传仍直接写可见目标，中断可能留下改变或部分内容；serve 上传和新的暂存下载有更强的发布保证。
- 部分远程覆盖确认细节仍有差异，`-f -y` 是明确的无人值守覆盖形式。
- Windows 无法表示全部 Unix 文件名；下载会拒绝本地驱动器、路径穿越及设备名组件，防止写出目标目录。

远程到远程、仅开放 SFTP 的账号仍是能力缺口，见 [scp 功能对照](./scp-compatibility.md)。
